## 現状

- **使われ方を測り始めたところ**：v2.29.0〜v2.37.0（11/5〜11/7）で、初めて来た人向けのページ、sitemap、公式パック71個ごとのページ、X でのシェア、Vercel Web Analytics、Search Console の登録を入れました。検索から来る人がどのページに着くかは、まだ数字がありません。
- **公式パックは269個**で、そのうち184個が Handwriting に使えます（中国語154・韓国語30。v2.38.0 から HSK5・6級レベル単語の4つを含む）。ブラウザーの中で手書きを読み取れるのは韓国語だけで、中国語は OS の手書き入力に頼っています。語学のタイピングのパックは英語・ロシア語が4つずつ、スペイン語・フランス語・ドイツ語は1つずつです。
- **練習のモードは3つ**（写して打つ・思い出して打つ・手書き）で、記録はリストごとの時間・ミス・正確率です。v2.42.0 から、記録に間違えた単語と回数（20語まで）を残し、ホームに苦手な単語を出して、その単語だけを練習できます。v2.46.0 から、苦手な単語だけの練習でミスなく打てた単語は苦手な単語から外れます。
- **土台はひと区切り**：v2.36.x で CI の検査（knip・staticcheck・カバレッジ）、Prisma の廃止、大きい画面の分割が終わりました。Web版は v2.41.1 で、iPad／Mac 版は 11/13 に GraphQL から REST へ戻りました。`/api/graphql` は v2.43.0 で消し、アプリの API は REST だけです。v2.43.3 でプラグインの層（`src/plugins`）をやめ、v2.44.0 で TSV の読み込みをやめました（単語ファイルは CSV だけ）。
- **残っている設計上の宿題**は、デザインレビューで見送った小さな項目（デスクトップのサイドバーの折りたたみ、記録の削除の取り消し、ガイドの目次の現在地）です。保存の仕組みの改善（Issue [#174](https://github.com/Sparklingstadt/typle-r/issues/174)）は、保存時間と `409` の計測をしないことにして 2026-11-25 に閉じました。残った項目（`records_split` の後始末、リストなどの操作の共通化、`schemaVersion`、`WorkspaceContext` の分割）は、必要になったときにその項目だけの Issue を立てます。

## テーマ

順番の理由になる3つの考えです。

1. **数字で決める**。使われ方を測る仕組みを入れたばかりなので、次に作るものは、その数字を見てから決めます。測る前に大きなものを作りません。
2. **覚える練習を深める**。Typle の中心は「覚えたい言葉を、打って覚える」ことです。打つ練習から、覚えたかどうかが分かる練習へ広げます。
3. **土台は小さく保つ**。使う人のいない経路と古い依存を残さず、1 PR に1項目で進めます。

| 使われ方の計測 | Web Analytics と Search Console で、公式パックのページ・ランディングの表示数と検索語を4週間ぶん集める。Analytics に練習の開始と結果の表示のイベントを足し、「着いた人のうち練習を始めた割合」を見られるようにする | 11月末の見直しで、どのパック・言語に人が来ているかを表にして「次」の順番を決められる |

| 依存の更新 | 範囲内の依存を月1回まとめて更新する。ESLint 10・TypeScript 7・`@types/node` 26・`cn` 0.5 は1つずつ別の PR にする | メジャーの更新が4つとも終わっている |

## その先（2027年2月以降）

- **間隔反復（SRS）**：v2.42.0 の苦手な単語の記録を元に、復習する日を決めて出す。設計は、苦手な単語の練習の使われ方を見てから。
- **手書きの次の言語**：日本語（かな・漢字）のモデル。パックがないので、パックと一緒に。
- **見本なしで書くモード**：意味から手で書く。思い出して打つモードの手書き版。

## やらないこと

- iPhone 版・Android 版のネイティブアプリ。アーカイブした typle-a・typle-w は直しません。スマホは Web で対応します。
- 評価・コメント、ほかのユーザーとの比較やランキング。
- 外部向けの API（`/api/v1` は v2.36.20 で消しました）。
- サーバーで画像を認識する手書き（費用と画像の送信を増やさない）。

## リスクと依存

| リスク | 影響 | 備え |
|---|---|---|
| 計測の数字が少なくて順番を決められない | 「次」の順番がそのまま | 11月末に数字が少なければ、順番を変えずに上から進める |
| 中国語の手書きモデルが大きい・精度が足りない | 「今」の項目が「次」へ | 入れる前にモデルの大きさと、HSK の単語で読み取れる割合を測る。足りなければ OS の手書き入力のままにして記録に残す |
| 単語ごとのミスの保存（v2.42.0）で記録のデータが増えた | 保存時間と転送量 | 保存の時間と大きさは測っていない（計測の仕組みは v2.60.9 で消した）。保存が遅い、大きすぎて断られる（`413`）といった問題が出たら、残す語数（20語）を減らす |
| 公式パックの更新を反映すると、自分で変えたリストが上書きされる | 練習する人のデータ | 変えた部分を残す規則を設計で決め、E2E で確かめてから出す |
| GitHub Actions が止まる（支払いの停止など） | PR の CI と公開（Release・デプロイ）、API の文書の公開（Docs deploy）が止まる | 手元で `npm run verify` を流し、手で公開する（`docs/release-workflow.md` の「CI が公開できないとき」）。Ruleset は一時的に無効にする |

## 進め方

- 1 PR に1項目。機能はマイナー、直しとリファクタリングはパッチを上げます（`CLAUDE.md` の Release workflow）。
- 設計の要る項目は `docs/superpowers/specs/` に設計を書いてから始めます。範囲外に書いたことは、このファイルの「次」か「その先」に移します。
- 公式パックを変えたら typle-ipad の `catalog.json` を作り直します。REST の API の変更は iPad／Mac 版と互換を保ちます。
- 月に1回（月末）、このファイルの「現状」と各段の項目を見直し、終わったものを消し、日付を更新します。
