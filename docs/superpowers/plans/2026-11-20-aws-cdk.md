# AWS への移行: 本番の CDK（PR 1 の続き）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 設計書の本番の構成（VPC・RDS・ECR・ECS Fargate・ALB・Route 53・ACM・Secrets Manager・CloudWatch）を `infra/` の CDK（TypeScript）で作れるようにし、イメージの push からマイグレーション・サービスの更新までを `scripts/deploy-aws.cjs` で行えるようにする。

**Architecture:** スタックは1つ（`Typle`、`ap-northeast-1`）。context の `phase` が `dns` ならホストゾーンと DNS のレコードだけを作り（委任の前）、`full` ですべてを作る。ゾーンの頂点のレコードは1つの `CfnRecordSet` で、context の `dnsTarget` が `vercel` なら Vercel（A 76.76.21.21）、`aws` なら ALB のエイリアスを向く（同じリソースを書き換えるので、切り替えのあいだに名前が消えない）。イメージのタグは context の `appTag`（サービス）と `migrateTag`（マイグレーションのタスク定義）で別に渡し、デプロイは「マイグレーションのタスク定義だけ新しく → 単発タスク → サービスも新しく」の2回の `cdk deploy` にする。

**Tech Stack:** aws-cdk-lib 2.277.0、aws-cdk（CLI）2.1149.0、constructs 10、Node.js 24（TypeScript を型の除去でそのまま実行）、`node:test` と `aws-cdk-lib/assertions`。

**Spec:** `docs/superpowers/specs/2026-11-20-aws-migration-design.md`（「構成（本番）」「マイグレーションとデプロイ」「データの移行」「CDK（本番）」）

## Global Constraints

- リージョン `ap-northeast-1`。ドメイン `typle.sparklingstadt.com`（Cloudflare から Route 53 に委任）。
- RDS: PostgreSQL 17、`db.t4g.micro`、gp3 20GB、シングル AZ、保存時の暗号化、自動バックアップ 7 日、削除保護あり、パブリックアクセスなし、`RemovalPolicy.SNAPSHOT`。
- NAT Gateway を作らない。タスクはパブリックサブネットでパブリック IP を持ち、セキュリティグループで ALB からの 3000 だけを受ける。
- Fargate: ARM64、0.5 vCPU / 1 GB、タスク1つ、ローリング（最小 100%・最大 200%）、サーキットブレーカーとロールバック。
- ALB: 443（ACM、DNS 検証）と、80 から 443 への 301。ヘルスチェック `/api/health`。
- Secrets Manager は器だけを作る。値は CDK のコードに書かない（作成時の値はランダムな仮の値。持ち主が CLI で入れ替える）。
- ECR: タグはイミュータブル、10 個まで残す、スタックを消してもリポジトリは残す。
- ログの保持 30 日。アラーム5つ（アプリの 5xx・ALB の 5xx・異常なターゲット・RDS の CPU・空き容量）、SNS のメール。メールアドレスはコミットしない（context `alarmEmail`）。
- 持ち主の個人情報（メールアドレス・アカウント ID）はリポジトリに書かない。
- `infra/` は自分の `package.json` を持ち、アプリの依存・`tsc`・`eslint`・`knip` に混ぜない（`api-docs/` と同じ扱い）。`npm run verify` に `infra` の検査（型・テスト・synth）を足す（`--fast` でも流す）。
- 文書は日本語、コードのコメントと識別子は英語。途中のコミットは日本語で内容だけ。

## Review Focus

1. **`phase=dns` で既存の本番を消す**: 本番ができたあとに `-c phase=dns` で deploy すると、ALB・ECS・RDS が消える。`phase` を省いたときは `full` にし、`dns` は明示したときだけにする。RDS は削除保護と SNAPSHOT で守られていることをテストで固定する → Task 2。
2. **切り替えで名前が消える**: 頂点のレコードは `vercel` と `aws` で同じ論理 ID の1つのリソースでなければならない → Task 2 のテスト。
3. **秘密がテンプレートに出る**: synth したテンプレートに秘密の値が平文で入らない。Secret は `GenerateSecretString` だけを持つ → Task 3 のテスト。
4. **アプリのタスクが DB のマスターパスワードを読める**: アプリの実行ロールが読めるのはアプリの秘密だけ。マスターはユーザー作成のタスクだけ → Task 3 のテスト。
6. **データ移行の行数の比較が甘い**: テーブルが片方にしかない、行数が違う、のどちらでも終了コードが 0 でない → Task 3 で `datamove.sh` を手元の PostgreSQL 2つに流して確かめる。
5. **マイグレーションより先に新しいアプリが出る**: デプロイの順序（push → migrate のタスク定義 → 単発タスクの終了コード 0 → サービス）を `deploy-aws.cjs` が守り、途中で失敗したら止まる → Task 4 のテスト。

### Task 4: デプロイのスクリプト

**Files:**
- Create: `scripts/deploy-aws.cjs`、`tests/deployAws.test.cjs`

**Interfaces:**
- `node scripts/deploy-aws.cjs [--profile typle]`。`package.json` の version から `v<version>` を作り、次の順に実行して、どれかが失敗したら止まる（終了コード 1）:
  1. `git status --porcelain` が空で、HEAD が `origin/main` と同じ（公開は main のコミットだけ）
  2. `docker build --platform linux/arm64 --build-arg SITE_URL=https://typle.sparklingstadt.com -t <RepositoryUri>:<tag> .` と `docker push`（ECR へのログインを含む）
  3. 今のサービスのイメージのタグを読み（`aws ecs describe-services` → `describe-task-definition`）、`cdk deploy Typle -c appTag=<今のタグ> -c migrateTag=<tag>`
  4. `aws ecs run-task`（`MigrateTaskDefinitionArn`、`TaskSubnetIds`、`TaskSecurityGroupId`、パブリック IP あり）→ `aws ecs wait tasks-stopped` → 終了コードが 0 か確かめる
  5. `cdk deploy Typle -c appTag=<tag> -c migrateTag=<tag>`（サービスが新しいタスク定義に変わり、CloudFormation が安定まで待つ）
  6. `npm run check:production`
- `githubClientId`・`mailFrom`・`alarmEmail` は `infra/cdk.context.local.json`（git 管理外）から読む。
- テストできる形: 実行する関数を `run(command, args)` として差し替えられるようにし（`module.exports = { deploy }`）、`tests/deployAws.test.cjs` で呼ばれた順と、途中の失敗で止まることを確かめる。
