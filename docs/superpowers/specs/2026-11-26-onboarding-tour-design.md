# はじめての人のツアー（設計）

## 目的

はじめて Typle を使う人は、今は /home の「ようこそ」か、/play の「どれから練習しますか？」（決まった3パック）に
着くだけで、自分の関心を選ぶ場面がない。関心をまだ保存していない人は「全部に関心がある」として扱われるので
（`DEFAULT_INTERESTS`）、カタログの「関心に合うパック」も全部になる。

ツアーが終わったとき、その人が**自分の関心に合う公式パックをフォローしていて、そのまま練習を始められる**状態にする。

## ゴール

- はじめて来た人を、専用の画面で「関心を選ぶ → パックをフォローする → 練習を始める」の3ステップで案内する。
- ログインした人にもゲストにも出す。
- 最後のステップから /play の練習にそのまま入れる。

## ゴールではないもの

- アプリのほかの画面（カタログ、/interests、記録など）の場所を教えること。
- 今の画面の上に吹き出しを出す案内（コーチマーク）。
- 関心の選択肢や公式パックそのものを増やすこと。
- ゲストのデータをアカウントに移すこと。

## 失敗とみなすもの

- すでに使っている人（データを保存したことがある人）にツアーが出る。
- 「あとで」を押したのに、開くたびにツアーに送られる。
- ツアーの途中で抜けた人のデータが中途半端に変わる（関心だけ狭まってパックがない、など。下の「保存」を参照）。
- 関心に中国語を選んだ人の前に約30パックが並び、そこで手が止まる。

## 考えた見せ方（Approaches）

| 案 | 中身 | 長所 | 短所 |
|---|---|---|---|
| **A. 専用の数ステップの画面（採用）** | 新しい画面1つで3ステップ。今の部品（関心・フォロー・練習の開始）を使う | 迷わず最後まで進める。作る量が少ない | ほかの画面の場所は覚えない |
| B. 今の画面の上の吹き出し | /interests → カタログ → /play を吹き出しで順に案内 | 実際の画面に慣れられる | 作るのも保つのも大変。/interests の操作の多さ（チェックボックス・スイッチ・まとめて操作）が残る |

目標が「フォローして練習を始められる」なので、持ち主は A を選んだ。

2ステップ目で見せるパックについても3案を比べ、持ち主は 1 を選んだ。

1. **関心ごとに、いちばん入りやすいパックを1つだけ、チェックを入れて出す（採用）**。ほかは「カタログでもっと見る」へ。
2. 関心に合うパックを全部出し、何もチェックしない（中国語で約30パック並ぶので不採用）。
3. 「はじめて／経験あり」も聞いてレベルで絞る（ステップが増え、レベルのないパックの扱いも要るので不採用）。

## 決まっていること

### 誰に、いつ出すか

- **はじめて来た人＝ワークスペースの版（`revision`）が 0 の人**。アカウント（`workspaceAnswer` は保存がなければ
  `revision: 0`）もゲスト（`readDocument` は localStorage になければ `empty(0)`）も同じ決まりで見分ける。
  新しい保存先や列は作らない。
  - 練習したことがある人は版が 0 ではない：練習にはパックが要り、パックのフォローは保存なので版が上がる
    （/play の3パックも、選ぶとフォローして保存する）。記録の追加も、アカウントは `typle_workspaces` の版を1つ上げ、
    ゲストは `addGuestRecord` で版を1つ上げる。v1.0.0 より前のゲストのデータは空として読まれるが、版は元のまま残るので出ない。
- 版が 0 の人が **/home か /play** を開いたら、ツアーの画面に送る。ログイン直後は `returnPath` の既定で /home に戻るので、
  新しく登録した人はここで送られる。トップページ（/）はそのまま（誰でも見るページなので）。
- **「あとで」**で抜けられる。抜けたら、そのブラウザーでは、そのアカウント（ゲストは `guest:local`）には自動では出さない。
  印はブラウザー（localStorage）にアカウント ID ごとに残すだけで、ワークスペースは変えない。
- ツアーははじめての1回だけ。/guide などから開き直す入口は作らない（持ち主の判断）。あとから関心やパックを変えるのは
  今の /interests とカタログで行う。ツアーの URL を版が 0 でない人が直接開いたときは /home に送る（すでにある関心や
  フォローをツアーで上書きしないため）。
- ツアーでフォローまで済めば保存が起きて版が 1 以上になるので、印がなくても次からは出ない。

### ステップ1：関心を選ぶ

- 親（「語学」「プログラミング」）と子（「中国語」「Go」など）を同じ画面に並べる。選び方の規則は `toggleInterest`
  と同じ（子は親を選んでいるときだけ選べる、親を外すと子も外れる）。見た目は `InterestSettings` のチップに合わせる。
- 子を1つ以上選ぶと「次へ」が押せる。
- ステップ1では保存しない（下の「保存」）。

### ステップ2：パックをフォローする

- 選んだ子ごとに、対応表（下）のパックを1つ、チェックを入れた状態で並べる。同じパックが2つの子から出るときは1回だけ並べる。
- 各パックは名前・リスト数・単語数・最初のリストの単語を2〜3語見せる（`StarterPacks` のカードと同じ情報）。
- チェックを外せる。チェックが1つ以上あれば「フォローする」が押せる。
- 「カタログでもっと見る」へのリンクを置く。
- 「フォローする」で、関心とフォローを保存する（下の「保存」）。

### ステップ3：練習を始める

- フォローしたパックのうち、ステップ2で上に並んでいた最初の1つの、最初のリストを見せる（名前と最初の数語）。
- 「練習を始める」で、そのリストの練習（`practicePath(list.id)`）に入る。ほかのパックはあとで /play から選べる。

### 保存

- ツアーで保存するのは、ステップ2の「フォローする」の1回だけ。関心はそこまで画面の中だけに持つ。
- 「フォローする」で、フォロー（`updateLibrary` と `applyCatalogChoices`）と関心（`updateInterests`、選んだものだけ）を保存する。
  **フォローを先に**保存する。フォローが失敗したら関心も保存せず、エラーを出してステップ2に留まる。
  フォローが成功して関心が失敗したときは、フォローは残したままエラーを出し、関心をもう一度保存できるようにする
  （パックがあれば練習は始められるので、目標は満たせる）。
- 関心を保存すると、それまでの既定（全部）ではなく選んだものだけになる。これは狙いどおり（カタログの「関心に合うパック」が絞られる）。

### 画面と言葉

- 新しいページ（例：`/welcome`）を `(workspace)` の下に作る。どちらの保存先でも動くこと。
- 6言語（ja・en・fr・ru・zh-CN・zh-TW）の文言を `src/messages/*/` に足す。

### テスト

- 単体テスト：対応表（上）、版が 0 で印がないときだけ送る判定。
- E2E（Playwright）：
  - ゲストではじめて /home を開く → ツアー → 関心を選ぶ → フォロー → 練習が始まる。保存されたワークスペースに、
    そのパックと選んだ関心だけがある。
  - 「あとで」→ もう一度 /home を開いてもツアーに送られない。
  - データのある人は /home・/play を開いてもツアーに送られず、ツアーの URL を直接開くと /home に送られる。
  - 今ある E2E とスクリーンショットのテストのうち、新しいゲストで /home・/play を開くものは、印を置くなどして
    ツアーに送られないようにする。
  - ログインした新しいアカウントでも送られる（今の E2E のログインの仕組みで）。

## 作る人に任せること

- ページの URL、ステップの見た目と動き（戻るボタンの有無、ステップの表示、アニメーション）。
- 版を画面に渡す方法（今の `useWordLists` は `revision` を返さない）。
- 送る処理の置き場所（/home と /play それぞれか、共通の部品か）。読み込み中にちらつかないこと。
- 印の localStorage のキー名。
- 文言（6言語）。
