# デモアカウントでのログイン

## 目的

typle-r はポートフォリオとして見られます。見に来た人（採用担当の方など）は、GitHub や Sparklingstadt ID のアカウントを
持っていないことも、使いたくないこともあります。ログインしなくてもアプリは使えますが、それではログインしたときだけの部分
（アカウントへの保存、ホームの記録の集計、別の端末との同期）が見えません。ボタン1つでデモアカウントに入り、
見本のデータが入った状態を試せるようにします。

## 目標・しないこと

- 目標：ログイン画面の「デモアカウントで試す」ボタン1つで、共有のデモアカウントにログインできる。入った直後から、
  単語リストと今週の練習の記録が見える。編集・練習・保存もふつうのアカウントと同じようにできる。
- 目標：デモのデータは毎日1回、決まった時刻に見本の状態へ戻る。
- しないこと：来た人ごとにアカウントを分けること（共有の1つにすると決めた）。デモアカウントの中身をほかの人から隠すこと。
- 失敗とみなすこと：デモの操作で、ほかの人のログインやデータに影響が出ること（「すべての端末からログアウト」で
  ほかの見学者が追い出される、など）。デモのログインが、ほかのアカウントに入れる経路になること。

## 方針の比較

| 案 | 内容 | 結果 |
|---|---|---|
| 来た人ごとに使い捨て | `demo:<ランダム>` を毎回作り、時間がたったら消す | 採らない（ユーザーが共有を選んだ） |
| 共有・ログイン時に戻す | 前に戻してから1時間たっていれば、ログインのときに戻す | 採らない。使っている人の途中で戻ることがある |
| **共有・毎日 cron で戻す** | Vercel Cron が毎日1回、戻す API を呼ぶ | **採る**（ユーザーが選んだ） |
| 共有・読み取り専用 | 書き込みを断る | 採らない。保存が試せない |

## 作り

### アカウント

- ID は `demo:shared`、名前は「デモアカウント」（6言語の訳は画面側。保存する名前は日本語の固定値で、
  `LOCAL_USER` と同じ扱い）。アドレスは `accountEmail('demo:shared')`。`accountIdFromEmail` の `ACCOUNT_ID` に
  `demo:shared` を足す。
- 本番でも使えます。`DEMO_LOGIN=1` のときだけ有効にします（既定は無効）。ローカルと E2E では `.env` で有効にします。

### ログイン

- 開発用ログイン（`src/server/localLogin.ts`）と同じ作りで、Better Auth のプラグイン `demoLogin` に
  `POST /api/auth/sign-in/demo` を足します。`formCsrfMiddleware` を使い、ユーザーがまだなければ作り、セッションを始めます。
- `src/server/authPaths.ts` の許可リストに、有効なときだけ `POST /sign-in/demo` を入れます。
- 1つの IP からの連打は Better Auth の rateLimit で抑えます（`/sign-in/demo` に 60 秒 20 回。具体的な数は私の判断）。
- 画面：`src/lib/session.tsx` に `signInDemo()`。ログイン画面のほかのボタンの下に、区切りと「デモアカウントで試す」
  ボタン（`variant="outline"`）と、「共有のアカウントです。入力した内容はほかの人にも見え、毎日 4:00（日本時間）に
  元に戻ります」という注意を置きます。デモが無効なら出しません。

### デモアカウントでは断ること

- `POST /api/account/signout-everywhere`：403 で断ります（ほかの見学者のセッションまで消えるため）。設定画面の
  ボタンもデモアカウントでは出しません。
- そのほかの操作（リストの編集・削除、練習、記録の削除、パックのフォロー、関心の変更）はふつうに通します。

### 見本のデータと戻し方

- 見本は `src/server/demoWorkspace.ts` にコードで持ちます：自分で作った単語リスト1〜2件と、公式パック2件のフォロー、
  関心（ツアーが出ないように設定済み）、過去7日に散らばった練習の記録。記録の日時は戻す時刻からの相対で作るので、
  いつ戻しても「今週のまとめ」に中身が出ます。
- 戻す処理 `resetDemoWorkspace(db, now)`：1つのトランザクションで `demo:shared` の記録を消し、ワークスペースを見本で
  書き直します。`revision` は1に戻さず、今の値より大きくします。開いたままの画面が古い revision で保存すると 409 になり、
  読み直すようにするためです。デモのセッションは消しません（ログインしたまま、中身だけが戻ります）。
- `GET /api/demo/reset`：Vercel Cron が `Authorization: Bearer $CRON_SECRET` を付けて呼びます。一致しなければ 401、
  デモが無効なら 404。`vercel.json` に `"crons": [{ "path": "/api/demo/reset", "schedule": "0 19 * * *" }]`
  （UTC 19:00 = 日本時間 4:00）。
- デモのユーザーが初めて作られるときにも、見本を書き込みます（cron を待たずに中身があるように）。

### 設定と運用

- 本番に要る環境変数：`DEMO_LOGIN=1` と `CRON_SECRET`。`docs/production.md` に書きます。ユーザーが Vercel に設定します。
- `infra/`（AWS）へ移るときは EventBridge で同じ API を呼ぶ必要があります。今回は README に一言書くだけにします。

## テスト

- 単体：`authPathAllowed` の `/sign-in/demo`（有効・無効）、`accountIdFromEmail('demo:shared@users.invalid')`、
  見本のワークスペースが `decodeDocument` を通ること、`resetDemoWorkspace` が記録を入れ替え revision を上げること（DB を使う）、
  `/api/demo/reset` の 401・404・200、デモでの signout-everywhere の 403。
- E2E：ログイン画面のボタンからデモに入り、ホームに見本のリストと今週のまとめが出ること。デモが無効なときボタンが出ないこと。
- README の「できること」に一行足し、`docs/features.md` に仕様を書きます。

## 実装する人に任せること

- 見本の単語リストの中身と、記録の件数・散らばり方。
- 文言の6言語の訳（既存の訳に合わせる）。
