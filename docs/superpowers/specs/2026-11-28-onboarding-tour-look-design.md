# はじめての人のツアーの見た目（設計）

v2.61.0 のツアー（`docs/superpowers/specs/2026-11-26-onboarding-tour-design.md`）の**見せ方だけ**を作り直す。
誰に出すか、3ステップの中身、保存の順番、対応表はその設計のまま変えない。

## 目的

今のツアーは、設定画面と同じ作り（小さな「ステップ 1 / 3」、見出し、チップ、右下のボタン）で、持ち主は
「設定画面みたいで味気ない」と感じている。はじめての人が最初に見る画面なので、**Typle がタイピングのアプリだと
ひと目で分かり、選ぶたびに自分の練習ができていく手応えがある**画面にする。

## ゴール

- タイピングのアプリらしい雰囲気（キーの形、打たれる見出し、キーボードで進める）。
- ステップ1で選ぶたびに、右のパネルに「あなたの最初の練習」が組み上がる。
- ステップ1 → 2 → 3 が、画面の切り替えではなく、つながった動きに見える。
- ステップ3で、最初の単語が練習と同じ見た目で打たれていく見本を見せ、Enter で本物の練習に入る。

## ゴールではないもの

- ツアーの流れ・出す条件・保存の仕方を変えること（前の設計のまま）。
- ステップ3で実際に打てるようにすること（案3として考えて不採用。下の Approaches）。
- ツアー以外の画面（/interests など）の見た目を変えること。キーの形の選択肢もツアーの中だけで使う。

## 失敗とみなすもの

- 動きのせいで操作が遅く感じる（アニメーションが終わるまで押せない、など）。
- 動きを減らす設定（`prefers-reduced-motion`）の人にも、打たれる見出しや見本のアニメーションが出る。
- キーボードの操作（Enter・Esc・数字・←）が、ボタンや入力のふつうの操作とぶつかる。
- スマホで右のパネルが選択肢を押し下げて、「次へ」が画面の外に出たままになる。
- ほかの画面のバンドルに motion が入る（ツアーの画面だけで読む）。

## 考えた作り方（Approaches）

| 案 | 中身 | 長所 | 短所 |
|---|---|---|---|
| 1. CSS だけで作り直す | `tw-animate-css` と CSS の動き。新しい依存なし | 軽い。今の部品と同じ作り | ステップの間のカードの動きがつながらない（消えて出るだけ） |
| **2. 1 に motion を足す（採用）** | 1 と同じ部品に、`motion` のレイアウトアニメーションを足す | ステップ1の右のカードが、ステップ2で主役になるまで滑らかにつながる。いちばん見栄えがよい | 依存が1つ増える。1回しか見ない画面のために読む量が増える |
| 3. ステップ3を本物の練習にする | 最初の単語をツアーの中で実際に打つ | 手応えが最大 | `PracticeScreen` にツアーの分岐が入る。記録の扱いを決める必要。今も Enter で本物の練習に入れるので得るものが少ない |

見た目の方向は、モックアップの3案（A. キーボードの中に入る／B. 大きなタイルと進み具合のバー／C. 選ぶと右に練習が
組み上がる）から、持ち主が **「A の雰囲気で C の右側」** を選んだ。作り方は持ち主が **2** を選んだ。

## 決まっていること（持ち主が決めた）

### 全体

- 2列：左に問いかけと操作、右に「あなたの最初の練習」のパネル（`primary` を薄くした背景）。
- 上に3つの短い棒で進み具合を示す（今の「ステップ 1 / 3」の文字の代わり。読み上げ用の文字は残す）。
- 右上に「あとで」と `Esc` のキー。

### ステップ1：関心を選ぶ

- 見出し「何を打てるようになりたい？」が1文字ずつ打たれるように出て、末尾にカーソルが点滅する。
- 関心はキーキャップの形のボタンで並べる（親の見出し「語学」「プログラミング」の下に子）。選ぶとキーが `primary` の色で押し込まれた形になる。
- 選ぶたびに、右のパネルにその関心の入りやすいパック（対応表のもの）がカードで入ってくる。カードには名前と最初のリストの単語を2〜3語。外すとカードが抜ける。
- 「次へ ↵」。

### ステップ2：パックをフォローする

- 画面は切り替えず、右のパネルが主役になる。ステップ1のカードがそのまま（motion で位置と大きさをつないで）残り、単語の代わりにリスト数・語数と、チェックのキー（`1` `2` `3`…）が付く。外したカードは薄くなる。
- 左には見出し（例「この3つから始めよう」）、カタログへのリンク、キーの案内、「フォローする ↵」。

### ステップ3：練習を始める

- 右のパネルは消え、1列になる。練習の画面そっくりに、フォローした最初のパックの最初のリストの最初の単語が大きく出る。
- その下で、入力の見本が練習と同じ色分け（`TargetText` の `done` / `current`）で1文字ずつ自動で進む。
- 「練習を始める ↵」で、今と同じく `practicePath(list.id)` に入る。

### 持ち主が残すと決めた3つ

1. **キーボードの操作**：Enter で次へ・フォローする・練習を始める、Esc で「あとで」、ステップ2で数字キーでチェックの切り替え。
2. **ステップ2 → 1 に戻る**：`←` キーと「戻る」のボタン。戻ってもチェックの状態は選んだ関心に合わせて残す（まだ何も保存していないので戻っても安全）。フォローを押した後（保存の後）は戻れない。
3. **ステップ3の入力の見本のアニメーション**。

## 決まっていること（作る人の判断として私が決めた。持ち主が見て直せる）

- **motion の読み込み**：`motion` パッケージ（React 用の `motion/react`）を使い、ツアーの部品からだけ import する。
  `/welcome` はクライアントの部品なので、ほかの画面のバンドルには入らない。軽くするために `LazyMotion` と `m` を使う。
- **動きを減らす設定**：`prefers-reduced-motion` のときは、見出しは最初から全部出す、カーソルは点滅しない、カードは動かさずに出し入れする（`MotionConfig reducedMotion="user"`）、ステップ3の見本は最後まで打ち終わった状態で止めて見せる。
- **アニメーションは操作を待たせない**：ボタンとキーは動きの途中でも効く。見出しを打つ動きは1文字40ms前後で、長くても1秒以内に終わる。
- **キーボードの操作がぶつからないように**：関心のキーとステップ2のチェックは、見た目はキーキャップでも中身は
  チェックボックス（`<input type="checkbox">` を隠してラベルをキーの形にする）にする。チェックボックスは Space で
  切り替わり Enter では何もしないので、**Enter はステップの中のどこにフォーカスがあっても**（見出し・キー・本文）
  そのステップの主ボタン（次へ・フォローする・練習を始める）を押したことにする。ほかのボタン（あとで・戻る）や
  リンク（カタログ）にフォーカスがあるときの Enter は、そのボタンやリンクの動作に任せる。ステップが変わったら
  見出しにフォーカスを移す今の動き（読み上げのため）は残す。数字キーは9つまで（それより多いパックは数字なしで
  クリックのみ）。修飾キー（Ctrl・Cmd・Alt）付きと、日本語入力の変換中（`isComposing`）は無視する。キーの案内は今の
  `Kbd` の見た目に合わせる。
- **親の関心（「語学」「プログラミング」）は押すキーではなく見出しにする**（持ち主が選んだモックアップのとおり）。
  子を選ぶと親も自動で入り、その親の最後の子を外すと親も外れる。これはツアーの中だけの規則として `src/lib/welcome.ts`
  に置き（単体テスト付き）、`toggleInterest` は変えない（/interests は今のまま親を選んでから子を選ぶ）。保存する関心は
  今と同じく親と子の組（`normalizeInterests` を通す）。今の `tests/e2e/welcome.spec.ts` の「語学」を押す手順は外す。
- **スマホ（`sm` より狭い幅）**：1列にして、右のパネルは選択肢の下に回し、選んだパックの名前だけの小さな行にまとめる（単語は出さない）。「次へ」の行は画面の下に固定する。
- **ダークモード**：色はすべてアプリのトークン（`primary`・`muted`・`border` など）から取る。
- **関心のキーの文字**：語学はその言語の名前をその言語の文字で（中文・Русский・한국어・English・Español・Français・Deutsch・Čeština）、その下に小さく今のタグ（「中国語」など）。プログラミングは今のタグを等幅の文字で。読み上げの名前は今のタグにする。
- **部品の置き場**：`src/components/Welcome/` に足す（キーのボタン、打たれる見出し、右のパネル、入力の見本）。`InterestSettings` は使わない。
- **motion の読み込み方の補足**：ステップの間でカードをつなぐレイアウトアニメーションには `LazyMotion` に `domMax` を渡す。
- **ステップ3の見本**：表示と入力が違う単語（中国語のピンインなど）は、練習の `WordPrompt` と同じく表示を上、入力を下の2段で出し、下の段を `TargetText` で進める。
- **読み上げ**：各ステップの `section` の名前は今の「関心を選ぶ」「パックをフォローする」「練習を始める」を保ち、画面に出る見出し（「何を打てるようになりたい？」など）はその中の見出しにする。
- **文言**：新しい見出しと案内を6言語（ja・en・fr・ru・zh-CN・zh-TW）の `src/messages/*/home.json` の `tour` に足す。
- **テスト**：今の `tests/e2e/welcome.spec.ts` が通るように、ボタンの名前と役割は保つ。キーボードで最後まで進める E2E（Enter・数字・←・Esc）を足す。`tests/e2e/screenshots.spec.ts` にツアーの3ステップを、動きを減らす設定で撮るスナップショットとして足す（macOS のみ）。aria のスナップショットも更新する。

## 作る人に任せること

- motion のアニメーションの細かい値（ばねの強さ、時間）。
- 右のパネルに何も選んでいないときの見せ方（例「関心を選ぶとここに練習が並びます」）。
- ステップ2の見出しの文言（パックの数による言い回し）。
- 部品の分け方と名前。
