# 3. データベース（RDS for PostgreSQL）

[← 手順書の一覧](README.md)

アプリの DB を、マネージドサービスの RDS で作ります。
OS やデータベースのソフトのパッチ、バックアップ、障害時の復旧は AWS が受け持ちます。利用者が受け持つのは、設定とデータとアクセスの管理です。

## 3-1. サブネットグループを作る

RDS をどのサブネットに置くかを決めるものです。

1. **RDS** → **サブネットグループ** → **DB サブネットグループを作成**を開きます。
2. 名前を `typle-lab-db`、VPC を `typle-lab-vpc` にします。
3. 2つの AZ を選び、それぞれの**プライベート**サブネット（名前に `private` が入っているもの）を選んで作成します。

## 3-2. データベースを作る

**RDS** → **データベース** → **データベースの作成**で、**標準作成**を選び、次のとおりに入れます。

| 項目 | 値 | 理由 |
|---|---|---|
| エンジン | PostgreSQL、バージョンは **17** の最新 | 手元の `compose.yaml` と同じメジャー版 |
| テンプレート | 無料利用枠（なければ開発/テスト） | |
| 可用性と耐久性 | **シングル AZ** の DB インスタンス | 練習なので。下の「マルチ AZ」を参照 |
| DB インスタンス識別子 | `typle-lab` | |
| マスターユーザー名 | `postgres` | |
| 認証情報の管理 | **AWS Secrets Manager で管理** | パスワードを自分で持たない |
| インスタンスクラス | バースト可能クラス、**db.t4g.micro** | いちばん小さい Graviton |
| ストレージ | **gp3**、20 GiB、ストレージの自動スケーリングはオフ | |
| コンピューティングリソース | EC2 コンピューティングリソースに接続しない | |
| VPC | `typle-lab-vpc` | |
| DB サブネットグループ | `typle-lab-db` | |
| パブリックアクセス | **なし** | インターネットから届かない |
| VPC セキュリティグループ | 既存のものを選ぶ: `typle-lab-db`（`default` は外す） | |
| データベース認証 | パスワード認証 | |
| モニタリング | Database Insights は**スタンダード**（無料）のまま（画面が古ければ Performance Insights はオフ）、拡張モニタリングはオフ | 費用のため |
| 最初のデータベース名（追加設定） | `typle` | |
| バックアップの保持期間 | 1日 | 練習なので。本番は7日 |
| 暗号化 | 有効（既定の `aws/rds` キー） | 保存時の暗号化 |
| 削除保護 | **オフ** | 練習なので片付けで消す。本番はオン |

作成には 10 分ほどかかります。状態が**利用可能**になったら、**接続とセキュリティ**の**エンドポイント**（`typle-lab.xxxx.ap-northeast-1.rds.amazonaws.com`）を控えます。

**設定**タブの**マスター認証情報の ARN**から、マスターユーザーのパスワードが入ったシークレットを開けます。
ここで見るだけにして、パスワードはどこにも書き写さないでください。アプリ用のユーザーは、[6](06-app.md) で別に作ります。

## 3-3. SSL が必須であることを確かめる

PostgreSQL 15 以降の RDS は、パラメータ `rds.force_ssl` が既定で `1` です。暗号化していない接続は断られます。
アプリは `DATABASE_URL` の `sslmode=verify-full` と、イメージに入っている RDS の CA バンドルで、接続先が本物の RDS であることまで確かめます（[production.md](../production.md) の「コンテナのイメージ」）。

## 確かめること

- [ ] `typle-lab` が利用可能で、パブリックアクセスが「なし」
- [ ] セキュリティグループが `typle-lab-db` だけ
- [ ] 暗号化が有効

## 試験のために

- **マルチ AZ**: 別の AZ に待機用のコピーを同期で持ち、障害のときに自動で切り替えます。**可用性**のためのもので、待機側は読み取りに使えません。料金はおよそ倍です。
- **リードレプリカ**: 非同期のコピーで、読み取りを分散して**性能**を上げるためのものです。別のリージョンにも置けます。
- **Amazon Aurora**: AWS 独自の、MySQL・PostgreSQL 互換のデータベースです。ストレージは自動で増え、データを3つの AZ に6つ持ちます。Aurora Serverless は使った分だけかかります。
- **データベースの選び方**:
  - リレーショナルなら RDS か Aurora
  - キーと値で大規模・低遅延なら **DynamoDB**（サーバーレス）
  - キャッシュなら **ElastiCache**
  - 分析（データウェアハウス）なら **Redshift**
  - 移行には **AWS DMS** を使います
- **RDS と EC2 に自分で入れた DB**: RDS では OS に入れませんが、パッチ・バックアップ・フェイルオーバーを AWS に任せられます（責任共有モデルの範囲が変わる例）。
