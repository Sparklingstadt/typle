# 1. アカウントの準備

[← 手順書の一覧](README.md)

ここでは、作業の前に3つを済ませます。

- root ユーザーを守る
- 普段の作業用のユーザーを作る
- 使いすぎたときに通知が来るようにする

## 1-1. root ユーザーを守る

AWS アカウントを作ったときのメールアドレスとパスワードのユーザーが **root ユーザー**です。すべての権限を持ち、権限を制限することもできません。

1. root ユーザーでコンソールにサインインします。
2. 右上のアカウント名 → **セキュリティ認証情報**を開きます。
3. **多要素認証（MFA）**で、MFA デバイスを割り当てます。パスキーか、認証アプリ（TOTP）を使います。
4. 同じ画面の**アクセスキー**が空であることを確かめます。root のアクセスキーは作りません。

これより後は、root ユーザーでは作業しません。root を使うのは、請求の一部の設定やアカウントの解約など、root にしかできない操作だけです。

## 1-2. 作業用のユーザーを作る（IAM Identity Center）

普段の作業は IAM Identity Center のユーザーで行います。長く使えるアクセスキーを作らずに、コンソールと CLI の両方を使えます。

1. リージョンを**東京**にして、**IAM Identity Center** を開き、**有効にする**を押します。
2. **ユーザー** → **ユーザーを追加**で、自分のユーザーを作ります。招待のメールが届くので、パスワードを決め、MFA を登録します。
3. **許可セット** → **許可セットを作成**で、定義済みの `AdministratorAccess` を選びます。名前はそのままで構いません。
   - 練習のために広い権限にしています。本番の運用では、必要な操作だけを許す許可セットに絞るのが望ましいです（**最小権限の原則**）。
4. **AWS アカウント**で自分のアカウントを選び、**ユーザーまたはグループを割り当て**から、2 のユーザーと 3 の許可セットを割り当てます。
5. **設定**に出ている **AWS アクセスポータルの URL** をブックマークします。今後はここからサインインします。

Mac の CLI も、同じユーザーで使えるようにします（AWS CLI v2 が必要です。`brew install awscli`）。

```bash
aws configure sso
# SSO session name: typle
# SSO start URL: <アクセスポータルの URL>
# SSO region: ap-northeast-1
# （ブラウザでの許可のあと）アカウントと AdministratorAccess を選ぶ
# Default client Region: ap-northeast-1
# Profile name: typle
aws sts get-caller-identity --profile typle
```

最後のコマンドで自分のアカウント ID が出れば成功です。この手順書のコマンドは、どれも `--profile typle` を付けます。
数時間たってサインインが切れたら、`aws sso login --profile typle` でもう一度サインインします。

## 1-3. 予算の通知を作る（AWS Budgets）

1. **Billing and Cost Management** → **予算** → **予算を作成**を開きます。
2. **カスタマイズ**、**コスト予算**を選び、名前を `typle-monthly`、期間を**月別**、金額を **80 USD** にします。
3. アラートを2つ足します。
   - 実際のコストが予算の **80%** を超えたとき
   - 予測のコストが予算の **100%** を超えたとき
4. 通知先に、自分のメールアドレスを入れます。

予算は**通知だけ**で、超えても AWS は止まりません。通知が来たら、自分で[片付け](09-cleanup.md)を進めます。

あわせて **Billing and Cost Management** → **請求設定**で、**無料利用枠の使用状況のアラート**を受け取る設定にしておくと安心です。

## 1-4. タグの約束

この手順書で作るものには、タグ `Project` = `typle-lab` を付けます。後で [9. 片付け](09-cleanup.md)のときに、タグで残りを探せます。

## 確かめること

- [ ] root ユーザーに MFA があり、アクセスキーがない
- [ ] アクセスポータルから自分のユーザーでサインインできる
- [ ] `aws sts get-caller-identity --profile typle` が通る
- [ ] 予算 `typle-monthly` があり、通知先が自分のメールになっている

## 試験のために

- **責任共有モデル**: AWS が守るのはクラウド**の**セキュリティ（建物・ハードウェア・仮想化の基盤）です。利用者が守るのはクラウド**の中**のセキュリティ（IAM・データ・OS やアプリの設定・ネットワークの設定）です。root の MFA は利用者の責任です。
- **IAM の用語**: ユーザー、グループ、ロール、ポリシー。IAM は**グローバル**なサービスで、リージョンを選びません。
- **IAM Identity Center**: 複数のアカウントへのシングルサインオン。**AWS Organizations** と組み合わせて使います。
- **料金の道具**: 予算を超えそうなときに知らせるのが **AWS Budgets**、使った額を分析するのが **Cost Explorer**、構成から月額を見積もるのが **AWS Pricing Calculator** です。
- **サポートプラン**: ベーシック、デベロッパー、ビジネス、エンタープライズ On-Ramp、エンタープライズの違い（応答時間、TAM の有無）も出題されます。
