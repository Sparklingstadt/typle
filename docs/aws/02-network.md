# 2. ネットワーク（VPC）

[← 手順書の一覧](README.md)

アプリと DB を置く、自分専用のネットワーク（VPC）を作ります。

- **パブリックサブネット**: インターネットから届く場所です。ALB とアプリのタスクを置きます。
- **プライベートサブネット**: インターネットから届かない場所です。DB を置きます。

どちらも、2つのアベイラビリティーゾーン（AZ）に1つずつ作ります。

## 2-1. VPC を作る

1. **VPC** → **VPC を作成**を開き、**VPC など**を選びます（サブネットやルートテーブルもまとめて作られます）。
2. 次のとおりに入れます。

   | 項目 | 値 |
   |---|---|
   | 名前タグの自動生成 | `typle-lab` |
   | IPv4 CIDR ブロック | `10.0.0.0/16` |
   | IPv6 CIDR ブロック | なし |
   | アベイラビリティーゾーンの数 | 2 |
   | パブリックサブネットの数 | 2 |
   | プライベートサブネットの数 | 2 |
   | NAT ゲートウェイ | **なし** |
   | VPC エンドポイント | なし |
   | DNS ホスト名・DNS 解決 | どちらも有効 |

3. タグ `Project` = `typle-lab` を足して作成します。

プレビューの図で、次のものができることを確かめてください。

- サブネット4つ
- インターネットゲートウェイ1つ
- パブリック用のルートテーブル（`0.0.0.0/0` がインターネットゲートウェイへ向く）と、プライベート用のルートテーブル

### NAT ゲートウェイを作らない理由

プライベートサブネットの中のものがインターネットに出るには、NAT ゲートウェイが要ります。NAT ゲートウェイは1つで月 40 ドル以上かかります。
この構成では、インターネットに出る必要があるのはアプリのタスクだけです（GitHub へのログイン、ECR からのイメージの取得、Secrets Manager）。
そこで、タスクをパブリックサブネットに置いてパブリック IP を持たせ、インターネットゲートウェイから直接出します。
外から届かないようにするのは、次のセキュリティグループの役目です。

## 2-2. セキュリティグループを作る

セキュリティグループは、リソースごとの**ステートフルな**ファイアウォールです。許可するものだけを書き、書いていないものはすべて拒否されます。

**VPC** → **セキュリティグループ** → **セキュリティグループを作成**で、VPC に `typle-lab-vpc` を選び、次の3つを作ります（作る順も表のとおりです）。

| 名前 | 用途 | インバウンドのルール |
|---|---|---|
| `typle-lab-alb` | ALB | HTTP（80）を `0.0.0.0/0` から、HTTPS（443）を `0.0.0.0/0` から |
| `typle-lab-app` | アプリのタスク | カスタム TCP 3000 を、ソース `typle-lab-alb`（セキュリティグループを選ぶ） |
| `typle-lab-db` | RDS | PostgreSQL（5432）を、ソース `typle-lab-app` |

- アウトバウンドのルールは、どれも既定（すべて許可）のままにします。
- ソースに IP アドレスではなく**セキュリティグループ**を指定すると、「そのグループに入っているものからだけ」という意味になります。
  そのため、DB に届くのはアプリのタスクだけ、アプリに届くのは ALB だけになります。

## 確かめること

- [ ] VPC `typle-lab-vpc` に、サブネットが4つある（パブリック2・プライベート2、それぞれ別の AZ）
- [ ] NAT ゲートウェイが1つもない（**VPC** → **NAT ゲートウェイ**が空）
- [ ] セキュリティグループが3つあり、`typle-lab-app` と `typle-lab-db` のソースがセキュリティグループになっている

## 試験のために

- **グローバルインフラストラクチャ**: リージョンは地理的な場所で、その中に物理的に離れた複数の**アベイラビリティーゾーン**（1つ以上のデータセンター）があります。**エッジロケーション**は、CloudFront と Route 53 が使う配信の拠点です。2つの AZ に分けて置くのは、1つの AZ が止まっても動き続けるためです（高可用性）。
- **セキュリティグループと ネットワーク ACL**:
  - セキュリティグループは、インスタンス（ENI）の単位で、ステートフル、許可だけを書きます。
  - ネットワーク ACL は、サブネットの単位で、ステートレス（戻りの通信も書く）、許可と拒否の両方を書けます。
- **接続の種類**: オンプレミスとつなぐ **Site-to-Site VPN**（インターネット経由・暗号化）と **Direct Connect**（専用線）、VPC どうしをつなぐ **VPC ピアリング**と **Transit Gateway** も出題されます。
