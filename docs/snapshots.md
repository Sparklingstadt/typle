# スナップショットテストの更新手順

画面の見た目と構造が意図せず変わっていないかを、E2E の中で確かめるテストです。v2.56.0〜v2.56.3 で入れました。
ここでは、テストが落ちたときの見分け方、期待値の更新のしかた、新しい画面の足し方をまとめます。

## 2種類のスナップショット

| | スクリーンショット | ARIA スナップショット |
| --- | --- | --- |
| テスト | `tests/e2e/screenshots.spec.ts` | `tests/e2e/aria-snapshots.spec.ts` |
| 期待値 | `tests/e2e/screenshots.spec.ts-snapshots/*-darwin.png` | テストの中に書いたものと、`tests/e2e/aria-snapshots.spec.ts-snapshots/*.aria.yml` |
| 比べるもの | 画面の画像（ピクセル） | アクセシビリティツリー（役割・名前・並び・状態） |
| 見つけられるもの | 色・余白・並び方・ダークモードの崩れ | ラベルの抜け、見出しのレベル、消えたリンクやボタン、数字や日付の誤り |
| 環境 | **macOS だけ**（フォントの描画が OS で違うため） | どの OS でも同じ |

どちらも `npm run test:e2e`（`npm run verify` の E2E）で毎回走ります。GitHub Actions の CI（Linux）では、スクリーンショットのほうだけ飛ばします（比べる画像が macOS のものだけのため）。データと時計を固定しているので、同じコードなら何度走らせても同じ結果になります。

## 前提

- テストは本番ビルドの `next start` に対して走ります。**アプリのコードを変えたら、先に `npm run build` を走らせてください。**
  古いビルドのまま撮ると、変更前の画面が期待値になります。
- ログイン中の画面は DB を使うので、手元の PostgreSQL（Docker）と `.env.local` の `DATABASE_URL` が要ります（`npm run verify` と同じです）。
- スクリーンショットの画像は macOS で撮ってください。Linux（Docker や CI）で撮った画像は、Mac では一致しません。

## テストが落ちたとき

まず、**変えるつもりの変更で落ちたのか、不具合で落ちたのか**を見分けます。期待値をすぐに書き直さないでください。

### スクリーンショット

落ちたテストごとに、`test-results/<テスト名>/` に次の3枚が出ます。

- `*-expected.png`：期待値（コミットされている画像）
- `*-actual.png`：今回撮った画像
- `*-diff.png`：違う所を赤で塗った画像

`*-diff.png` を見て、赤い所が今回の変更の範囲だけなら、意図した変更です。変えていない画面や場所が赤いなら、不具合か、テストが揺れています（「よくある失敗」を見てください）。

### ARIA スナップショット

テストの出力に、期待値（`- Expected`）と実際（`+ Received`）の差が行ごとに出ます。

```text
-   - button "このパックで練習する" [disabled]
+   - button "このパックで練習する"
```

ARIA スナップショットは、期待値を**含んでいれば**一致とみなします。実際のツリーに要素が増えただけでは落ちず、期待値にある要素がなくなったり、名前や順番が変わったりしたときに落ちます。

## 期待値を更新する

意図した変更だと確かめてから更新します。`-g` でテストの名前を絞ると、関係するものだけを書き直せます。

### 1. スクリーンショット

```bash
npx playwright test tests/e2e/screenshots.spec.ts --update-snapshots
```

特定の画面だけなら `-g` を付けます。

```bash
npx playwright test tests/e2e/screenshots.spec.ts -g "the sign-in page" --update-snapshots
```

撮り直したら、**変わった画像を1枚ずつ開いて**、狙いどおりかを確かめます（`git status` で変わったファイルが分かります）。
PR の画面でも、GitHub が画像の前後を並べて見せてくれます。

テストを消したり画像の名前を変えたりしても、古い画像は自動では消えません。使わなくなった `*-darwin.png` は手で消してください。

### 2. ARIA スナップショット（テストの中に書いたもの）

ログイン・登録・使い方の目次・トップバー・練習の結果・行のメニュー・CSV の読み込み・編集をやめるときの確認は、期待値をテストの中に書いています。

```bash
npx playwright test tests/e2e/aria-snapshots.spec.ts --update-snapshots --update-source-method=overwrite
```

**注意**：Playwright は書き直すとき、数字・日付・時刻を正規表現（`/\d+/` など）に置き換えます。練習の結果のテスト（所要時間 `6.00秒`・正確率 `95.2%`・速度 `200打/分`・`20 文字`）は時計を固定していて決まった値で比べているので、`git diff` を見て実際の値に戻してください。

### 3. ARIA スナップショット（ファイルに分けたもの）

ホーム・記録・設定・編集・練習のモード・ログイン中・共有・エラー・英語の表示などは、期待値が長いので `aria-snapshots.spec.ts-snapshots/*.aria.yml` に分けています。これらは `--update-snapshots` ではなく、次のコマンドで書き直します。

```bash
TYPLE_ARIA_WRITE=1 npx playwright test tests/e2e/aria-snapshots.spec.ts
```

`TYPLE_ARIA_WRITE=1` を付けると、テストは比べる代わりに、今のツリーをそのまま期待値のファイルに書き出します（`matchAriaFile`）。

- 数字・日付・時刻は**実際の値のまま**書き出します（`--update-snapshots` のように正規表現にしません）。
- アプリのバージョン（`v2.56.3` など）だけは、PR のたびに変わるので `/v\d+\.\d+\.\d+/` にします。
- 書き出す前に、0.5秒おいて2回読んだツリーが同じになるまで待ちます（読み込み途中の状態を書き出さないため）。

書き出したら `git diff` で差を確かめ、もう一度 `TYPLE_ARIA_WRITE` なしで走らせて通ることを確かめます。

### 4. 手で書いた期待値

公式パックの一覧（`catalog.aria.yml`）・関心（`interests.aria.yml`）・トップページ（`landing.aria.yml`）・ライセンス（`licenses.aria.yml`）は、期待値を手で書いています。`TYPLE_ARIA_WRITE=1` でも書き出されません。

これらの画面は、公式パックや依存パッケージが増えると一覧が変わります。そこで、見出し・説明・操作と、一覧の1件目の形だけを書き、件数は正規表現にしています。

```yaml
  - region "公式パック":
    - heading "公式パック" [level=2]
    - paragraph: /\d+件の公式リストを、フォローしてすぐに練習できます。/
```

画面の文言や操作を変えたときは、このファイルを直接直します。今のツリー全体を見たいときは、テストの中で `console.log(await page.getByRole('main').ariaSnapshot())` を一時的に足して走らせると出ます。

### 5. 更新したあとの確認

```bash
npx playwright test tests/e2e/screenshots.spec.ts tests/e2e/aria-snapshots.spec.ts --repeat-each=3
```

3回とも通れば、揺れていません。最後に `npm run verify` を通してから PR を出します。

## 新しい画面を足す

### どちらに足すか

- 見た目（色・レイアウト・ダークモード）を守りたい → スクリーンショット
- 文言・ラベル・ボタン・数字を守りたい → ARIA スナップショット
- 大事な画面は両方に足します。

### 毎回同じ画面にする

| 変わるもの | 固定のしかた |
| --- | --- |
| 単語リストと記録 | `tests/e2e/snapshotData.ts` の `seedSaved(page)`。2リストのパックと、2台の端末での記録をブラウザーに入れ、時計を 2026年11月1日（日）の正午に固定します |
| 練習の時間 | `page.clock.install({ time })` してから `page.clock.pauseAt(...)` で止め、単語の間で `page.clock.runFor(ミリ秒)` で進めます。経過・速度・所要時間が決まった値になります |
| 日付の表示 | `test.use({ timezoneId: 'Asia/Tokyo' })`（両方のファイルで指定済み） |
| アプリのバージョン | スクリーンショットは `masks(page)` で塗りつぶします。ARIA は自動で正規表現になります |
| 公式パックの数 | スクリーンショットは塗りつぶすか、その画面を撮りません。ARIA は手で書いた期待値で正規表現にします |
| ログイン中のユーザー | `tests/e2e/account.ts` の `signIn`。名前はいつも E2E User、ID はテストごとにランダムです。`afterEach` で `deleteWorkspace` を呼んで DB の行を消します |

### 読み込みが終わるのを待つ

ページを開いた直後は、まだ読み込み中のことがあります。**撮る前に、読み込みが終わったと分かる要素を待ってください**（各テストの `ready`）。

これまでに見つかった、読み込み途中の状態の例です。

- ログイン中のホームが「読み込み中…」のまま → 見出しを待つ
- 公式パックのページの「このパックで練習する」が押せない → `toBeEnabled()` を待つ
- Typleについての「今の保存先」がまだ出ていない → その文字を待つ
- 記録の画面がまだ空 → 記録の行の数（`toHaveCount(5)`）を待つ

### 画面の下が隠れるとき

編集の画面は、画面の下に固定された保存バーが内容に重なります。`fullPage: true` で撮るとバーが途中に写り込むので、`page.setViewportSize({ width: 1280, height: 1200 })` のように画面を高くして撮ります。

## よくある失敗と対処

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| 並列で走らせたときだけ落ちる | 読み込み途中の状態を期待値にしている | 読み込みの終わりを待つ要素を `ready` に足し、期待値を書き直す |
| `toHaveScreenshot` が「安定した画像を撮れない」とタイムアウトする | 時計で動く表示（経過時間など）がある | 時計を止めるか、その部分を `mask` で塗りつぶす |
| `ariaSnapshot` がタイムアウトする | メニューやダイアログを開いていて、ほかの部分が支援技術から隠れている | メニューを開く前に読む |
| ループで回しているテストが、1画面以外すべて落ちる | テストの中に書く期待値は、ループでは同じ場所に上書きされる | `matchAriaFile(locator, '<名前>.aria.yml')` でファイルに分ける |
| バージョンを上げただけで落ちる | バージョンが塗りつぶし・正規表現になっていない | `masks(page)` を渡しているか、ARIA のファイルが `/v\d+\.\d+\.\d+/` になっているかを見る |
| 公式パックを足しただけで落ちる | 公式パックの一覧や件数が期待値に入っている | 件数を正規表現にするか、その部分を期待値から外す |
| Linux で撮った画像が Mac で落ちる | フォントの描画が OS で違う | Mac で撮り直す |
